################################################################################
# 0. EXECUTIVE SUMMARY — WHAT THIS SYSTEM IS
################################################################################

FTTH Insight Hub monitors the fiber-to-the-home (FTTH) SALES FUNNEL and
TERRITORY/MARKET performance for "Circle Java" (Central Java + East Java) and
the wider Indonesia circles. It answers:

  1. SALES FUNNEL  : How many orders convert SO -> SA -> PA, by whom, where,
                     which product, vs target, vs last month.
  2. TERRITORY/TUR : How well is built fiber (homepass) being utilized
                     (Take-Up Rate), where is idle capacity, net adds.
  3. MARKET SHARE  : Indosat HiFi's share vs competitors per territory.
  4. PEOPLE        : Per-person/team productivity, cost efficiency (cost ratio).
  5. REPORTING     : Automated daily email (HTML + Excel + PDF) reports.

THE THREE FUNNEL STAGES (the heart of everything):
  SO = Service Order      (a customer ordered FTTH; counted on date_so)
  SA = Service Active     (service was activated; counted on date_sa)
  PA = Permanent Active   (became a permanent/billing subscriber; on date_pa)
  Funnel: SO -> SA -> PA. PA is the money/revenue event.
  IMPORTANT TERMINOLOGY:
    PA = "Permanent Active" (NOT "provisioning active").
    AP = "Advance Payment" product (multi-month prepaid FTTH package).
    TUR = "Take-Up Rate" = PA / homepass.
    MTD = Month-To-Date. LMTD = Last Month-To-Date. LLMTD = month before LMTD.

CRITICAL DESIGN RULE #1 — MULTI-DATE COUNTING:
  Each funnel stage is counted on ITS OWN event date, never a shared date.
    SO count  = rows where date_so in period
    SA count  = rows where has_sa=1 AND date_sa in period
    PA count  = rows where has_pa=1 AND date_pa in period
  This means a single order contributes to SO in the month it was ordered,
  SA in the month it activated, PA in the month it became permanent — possibly
  three different months. Do NOT use a single "transaction date".

CRITICAL DESIGN RULE #2 — MTD CUTOFF ("apples-to-apples"):
  "Today" for MTD is the MAX DATA DAY actually loaded (e.g. data up to the 14th),
  NOT the calendar day. The same day-of-month cap is applied to the current
  month AND prior months so MTD vs LMTD vs LLMTD compare equal windows:
    current : date_so in current month AND DAY(date_so) <= cutoff_day
    LMTD    : date_so in prev month    AND DAY(date_so) <= cutoff_day
  Reports/files are titled with the DATA date, not the run date.

CRITICAL DESIGN RULE #3 — TWO ANALYTIC DOMAINS, DIFFERENT GRAINS:
  A) TRANSACTION/FUNNEL domain  -> per-order facts (SO/SA/PA), revenue, sales
     hierarchy. Source = db_ftth_so/sa/pa -> pre-joined into ftth_raw_joined.
  B) SITE/TUR domain            -> per-site MONTHLY snapshot (homepass, pa,
     net add). Source = db_ftth_sitewise_monthly.
  C) MARKET SHARE domain        -> per-kabkota WEEKLY snapshot of all operators.
     Source = fb_ms_ftth.
  These three never mix at the row level; keep them as separate fact tables.

# 1. SALES & TERRITORY HIERARCHY (the dimensional backbone)
################################################################################

SALES HIERARCHY (top -> bottom):
  Circle  ->  Sales Region (Region Head/RM)  ->  Sales Manager (SM)
          ->  Team Leader (TL)  ->  Account Executive (AE / sales_code)

  - "Circle" is NOT stored on transaction rows; it is DERIVED from sales_region
    via a mapping table (tbl_ftth_region_head). A circle filter expands to a
    set of sales_region values.
  - AE identity = sales_code (+ sales_name). TL = sales_tl. SM = sales_manager.
    Region = sales_region.

TERRITORY HIERARCHY (geographic, independent of sales hierarchy):
  Circle -> Province (provinsi) -> Kabupaten/Kota (city/kabkota)

Currently MySQL DB "Kalisula" (loaded by an external ETL twice daily 03:30 &

--------------------------------------------------------------------------------
2.1 db_ftth_so  (one row per Service Order — the funnel entry)
--------------------------------------------------------------------------------
  bill_acc           BIGINT     -- billing account = the order key (join key)
  date_so            DATE       -- order date (SO event date)
  customer_id        VARCHAR
  username           VARCHAR
  province           VARCHAR     city VARCHAR     ward VARCHAR     street VARCHAR
  site_sitac         VARCHAR
  sales_code         VARCHAR     -- AE identity
  sales_name         VARCHAR
  sales_tl           VARCHAR     -- Team Leader
  sales_manager      VARCHAR     -- Sales Manager
  sales_region       VARCHAR     -- Region (maps to Circle)
  product            VARCHAR     -- product name (encodes AP/Regular, see 4.2)
  price              DECIMAL(15,2) -- monthly price (revenue basis)
  year_month         VARCHAR     date_val INT
  site_id            VARCHAR
  site_project_awal  VARCHAR     -- raw project (maps to ORBIT/NON-ORBIT/IFORTE)
  site_market        VARCHAR
  month_so, month_dt_id VARCHAR
  latitude DOUBLE    longitude DOUBLE   geocode_status VARCHAR
  shp_kabkota, shp_kecamatan, shp_desa VARCHAR  -- shapefile-normalized geo

--------------------------------------------------------------------------------
2.2 db_ftth_sa  (Service Active events; subset of SO by bill_acc)
--------------------------------------------------------------------------------
  Same columns as SO plus: date_sa DATE, date_so DATE, so_index DATE.
  Key = bill_acc. A bill_acc here means it reached SA.

--------------------------------------------------------------------------------
2.3 db_ftth_pa  (Permanent Active events; subset of SA by bill_acc)
--------------------------------------------------------------------------------
  Same columns as SO plus: date_pa DATE, date_so DATE, so_index DATE.
  Key = bill_acc. A bill_acc here means it reached PA. price here = revenue.

--------------------------------------------------------------------------------
2.4 db_ftth_sitewise_monthly  (per-site MONTHLY snapshot — TUR domain)
--------------------------------------------------------------------------------
  PK ~ (month_id, site_id, brand). One row per site per month.
  month_id        VARCHAR(6)  -- 'YYYYMM'
  site_id, site_name, system_key, map_id, territory_id
  brand           VARCHAR     -- "Orbit" / "Non Orbit" flag (FILTER: flag)
  vendor, market, status_area
  homepass        INT/DEC     -- total premises passed by fiber (capacity)
  available_hp    INT/DEC     -- idle capacity = homepass - pa
  pa              INT/DEC     -- CUMULATIVE active subscribers (snapshot)
  pa_net_latest   INT/DEC     -- MONTHLY NET ADD (can be negative = churn)
  ga              INT/DEC     -- gross add in month
  grouping_pa_net VARCHAR     -- pre-bucketed TUR band ('0% - 10%'..'100%+')
  lat, lng, area_size_m2, area_size_sqkm
  provinsi, city, kecamatan, kelurahan, kota_v2
  region_25       VARCHAR     -- territory region code (same codes as 1. above)
  regional_head, manager, team_leader, nama_sales, sales_code
  project_awal    VARCHAR     -- project (ORBIT/NON-ORBIT/IFORTE/Other)
  NOTE: "pa" (cumulative subs) here is a DIFFERENT meaning from the funnel "PA
        count" in the transaction domain. Keep them mentally separate.

--------------------------------------------------------------------------------
2.5 fb_ms_ftth  (per-kabkota WEEKLY market-share snapshot — MS domain)
--------------------------------------------------------------------------------

  For each of 9 operators, 3 wide columns: {ga|churn|total}_{op}
    operators: im3, hifi, xl_home, indihome_tsel, biznet, myrepublic, cbn,
               icon, oth

  Operator display names: hifi=Indosat HiFi, indihome_tsel=IndieHome,
    xl_home=XL Home, biznet=Biznet, myrepublic=MyRepublic, cbn=CBN,
    icon=ICON+, oth=Others.
  Territory join table: zz_territory_kecamatan (kabkota -> region, circle).
    Must DEDUPE to one row per UPPER(kabkota) via MAX(region), MAX(circle).

# 3. TRANSFORMED (CACHE) DATA MODEL  +  ETL LOGIC
################################################################################

The app pre-computes cache tables (in MySQL DB "db_ftth_app") because querying
380K+ source rows live is 5-6s. Refresh runs daily 05:00 via refresh_cache.php
using a zero-downtime TEMP-TABLE SWAP:
   CREATE <t>_tmp LIKE <t>;  bulk INSERT;  RENAME <t>->_old,_tmp-><t>;  DROP _old;
   then UPDATE <t> SET circle = COALESCE(region_head.circle_name,'OTHER').
[BQ] Replace swap with CREATE OR REPLACE TABLE / partition overwrite / MERGE,
     and derive `circle` via JOIN to a region dimension during the SELECT.

--------------------------------------------------------------------------------
3.1 ftth_raw_joined  (THE MASTER FACT — 1 row per bill_acc)  *most important*
--------------------------------------------------------------------------------
  Built by: db_ftth_so so
            LEFT JOIN db_ftth_sa sa ON so.bill_acc=sa.bill_acc
            LEFT JOIN db_ftth_pa pa ON so.bill_acc=pa.bill_acc
  Columns:
    bill_acc, date_so, date_sa, date_pa
    has_sa  = (sa.bill_acc IS NOT NULL) ? 1 : 0
    has_pa  = (pa.bill_acc IS NOT NULL) ? 1 : 0
    status  = CASE WHEN has_pa THEN 'PA' WHEN has_sa THEN 'SA_ONLY'
                   ELSE 'SO_ONLY' END
    days_so_sa = DATEDIFF(date_sa, date_so)   -- activation cycle time
    days_so_pa = DATEDIFF(date_pa, date_so)   -- full conversion cycle time
    customer_id, username, province, city, ward, street
    sales_code, sales_name, sales_tl, sales_manager, sales_region
    circle  (derived from sales_region via region dimension)
    product, price, site_id, site_project_awal, site_market
    latitude, longitude, shp_kabkota, shp_kecamatan, shp_desa
  EVERY funnel metric in the app is computed from this table as:
    SO  = COUNT(*) where date_so in window
    SA  = COUNTIF(has_sa=1 AND date_sa in window)
    PA  = COUNTIF(has_pa=1 AND date_pa in window)
    Revenue(SO) = SUM(price) over SO-window rows
    Revenue(PA) = SUM(IF(has_pa AND date_pa in window, price, 0))
    Avg cycle days = AVG(days_so_pa) over PA rows
[BQ] This is your central fact table. Model it exactly; all funnel dashboards
     are GROUP BYs over it with the multi-date counting rule.

--------------------------------------------------------------------------------
3.2 ftth_daily_sales  (grain: day x sales_code x product x city)
--------------------------------------------------------------------------------
  GROUP BY date_so, sales_code, product, city (from SO LEFT JOIN SA LEFT JOIN PA)
  Measures: so_count, sa_count, pa_count, revenue_so, revenue_pa,
            sum_days_so_pa, cnt_days_so_pa (lead-time accumulators)
  Dimensions carried via MAX(): sales_name/tl/manager/region/province, circle.
  Powers: dashboard filter lists + as a daily aggregate.

--------------------------------------------------------------------------------
3.3 ftth_geo_summary  (grain: month x city x ward)
--------------------------------------------------------------------------------
  GROUP BY DATE_FORMAT(date_so,'%Y-%m'), city, ward
  Measures: so_count, sa_count, pa_count, so_only_count, revenue_so,
            revenue_pa, avg_price_pa, sum_days_so_pa, cnt_days_so_pa
  Province/shp_*/lat/lng carried via MAX()/AVG() (NOT grouped).
  GOTCHA: a city/ward under >1 province causes duplicate unique-keys -> use
  MAX(province) so (month,city,ward) stays unique.

--------------------------------------------------------------------------------
3.4 ftth_mtd_tracker_daily  (+ geo variant)  — the MTD tracker pre-agg
--------------------------------------------------------------------------------
  Built by refresh_mtd_tracker_cache.php; trailing 24 months; idempotent
  (DELETE month window then 3 INSERT..SELECT, one per metric):
    SO: metric_type='SO', count by date_so
    SA: metric_type='SA', count by date_sa where has_sa=1
    PA: metric_type='PA', count by date_pa where has_pa=1
  Grain: (tanggal, metric_type, sales_region, sales_manager, project_group)
  Measures: cnt=COUNT(*), revenue=SUM(price); circle derived.
  Geo variant ftth_mtd_tracker_geo_daily: grain (tanggal, metric_type,
    province, city, project_group).
  Auto-refresh: if MAX(date_*) in raw_joined newer than MAX(tanggal) in cache,
  rebuild trailing 3 months on-the-fly.
[BQ] Implement as a scheduled aggregate table (or just GROUP BY raw fact at
     query time — BigQuery is fast enough to skip this pre-agg).

--------------------------------------------------------------------------------
3.5 Filter caches  (fast cascading dropdowns)
--------------------------------------------------------------------------------
  ftth_cache_hierarchy (~6K): distinct region>manager>tl>sales_code(+name)+circle
  ftth_cache_geo (~150): distinct province, city
  ftth_cache_product (~55): distinct product

3.6 ftth_cache_meta  (freshness tracking)
--------------------------------------------------------------------------------

################################################################################
# 4. SHARED BUSINESS LOGIC / FORMULAS  (replicate as BQ UDFs / shared SQL)
################################################################################

4.1 GROWTH %  (universal)
    growth = (curr - prev) / prev * 100
    if prev = 0 and curr > 0 -> 100 ;  if both 0 -> 0
    gap = curr - prev

4.2 AP (ADVANCE PAYMENT) PRODUCT CLASSIFICATION
    Detector regex on product name:  ^(AP|Super[ ]?)[0-9]+
      type    = 'AP' if matches else 'Regular'
      months  = leading integer = prepay duration (AP: 3,4,6,7,12 ; Super: 6,12)
      family  = 'AP' (^AP[0-9]+) or 'Super' (^Super ?[0-9]+) or NULL
      base    = product with the "AP{n}.../Super {n}..." prefix stripped
    Bucket label = CONCAT('AP', months) e.g. AP3/AP4/AP6/AP7/AP12; else 'Regular'.
    Filter modes: ''/'all'=no filter; 'AP'=all AP+Super; 'Regular'; 'AP12'
      (matches ^AP12 and ^Super ?12); 'family:AP'; 'family:Super'.

4.3 PROJECT GROUP CLASSIFICATION  (from site_project_awal, case-insensitive)
    ORBIT     <- contains 'mplay'
    NON-ORBIT <- contains 'seahawk' or 'spartan'
    IFORTE    <- contains 'iforte' / 'i-forte' / 'i_forte'
    Other     <- NULL/empty/anything else
    Used as a filter ("mode": BLENDED=all, ORBIT, NON-ORBIT, IFORTE) and a
    breakdown dimension across modules.

4.4 CONVERSION RATES (funnel)
    Conv SO->SA = SA/SO*100
    Conv SA->PA = PA/SA*100
    Conv SO->PA = PA/SO*100   (overall funnel efficiency)

4.5 TUR (TAKE-UP RATE)  — site/territory domain
    TUR % = SUM(pa) / SUM(homepass) * 100      (pa = cumulative active subs)
    Available % = available_hp / homepass * 100
    Net Add = SUM(pa_net_latest)               (monthly, can be negative)
    Churn (derived) = max(0, GA - Net Add)
    5-SLAB segmentation (acquisition view):
      extreme_low <10% | low 10-20% | mid 20-30% | high 30-50% | strong >=50%
    Map-tur summary buckets differ: low<20 | mid 20-30 | high 30-50 | elite>=50
    Source pre-bucket grouping_pa_net (11 bands) maps to the 5 slabs:
      0-10%->extreme_low; 10-20%->low; 20-30%->mid; 30-40%&40-50%->high;
      everything >=50% (incl 100%+)->strong.
    PA Extraction % = PA_month / available_hp * 100  (acquisition efficiency)
    SO Extraction % = SO_month / available_hp * 100

4.6 MARKET SHARE  (MS domain; industry excludes im3)
    industry_X = SUM over 8 operators of X (X in {total,ga,churn})
    Market Share % = operator_total / industry_total * 100
    SoGA % (Share of Gross Add) = operator_ga / industry_ga * 100
    SoChurn %                   = operator_churn / industry_churn * 100
    Net Add = ga - churn
    Delta WoW = current snapshot - previous snapshot value
    Delta YoY = current - snapshot nearest to (current_date - 364 days)
    Monthly mode = take the LATEST dt_id within each month (NOT sum of weeks).
      [BQ] QUALIFY ROW_NUMBER() OVER(PARTITION BY month ORDER BY dt_id DESC)=1
    Opportunity score = low operator MS% (< threshold, default 5%) AND high
      industry GA (sort by industry_ga desc) = "where the market is moving but
      we're weak".

4.7 ACHIEVEMENT vs TARGET
    Targets stored per Sales Manager per month for metric PA only
      (table tbl_ftth_target_sm: sales_manager, target_bulan, metric_type='PA',
       target_value).
    Achievement % = PA_curr / target * 100   (ALWAYS measured on PA, not SA)
    Gap = PA_curr - target
    Traffic light: <80% red, 80-95% amber, >=95% green.

4.8 COST RATIO  (people-cost efficiency)
    Per-level monthly cost from config (defaults: AE=3,800,000; TL=7,000,000;
      SM=20,000,000; RM configurable) in tbl_ftth_cost_config.
    headcounts via COUNT(DISTINCT sales_code / sales_tl / sales_manager /
      sales_region).
    total_cost = AE_cnt*AE_cost + TL_cnt*TL_cost + SM_cnt*SM_cost + RM_cnt*RM_cost
    cost_ratio % = total_cost / revenue_pa * 100   (999.99 if revenue=0)
    gap = total_cost - revenue_pa  (positive = loss)
    BEP_pa = ceil(total_cost / avg_price_pa)
    SO_needed_BEP = ceil(BEP_pa / hist_conv_so_pa)
    Ideal (10% target): ideal_pa = ceil(total_cost / (0.10*avg_price_pa))
    Status: ratio>100 LOSS; >=95 BREAK-EVEN; >10 BELOW TARGET; else IDEAL.

4.9 MTD CUTOFF / TRENDED TRIO (used by tracker + all reports)
    cutoff_day = DAY( MAX(date_so) in data )   [the locked "today"]
    Trio per metric: prev2 (LLMTD, month-2), prev1 (LMTD, month-1), curr (MTD),
    each capped at DAY(col) <= cutoff_day. growth = (curr-prev1)/prev1*100.

4.10 DORMANCY / STREAK (heatmap, evaluation, people)
    dormant threshold (days) = max(3, floor(cutoff_day * 0.2)) (and cutoff>=5)
    streak = consecutive active days; dormant_days = trailing zero days.
    Evaluation issue flags (relative to team averages of active AEs, so>0):
      zero_performer so=0; low_so 0<so<avgSO*0.5; low_conversion so>=3 AND
      (pa/so)<avgConvPA*0.5; slow_activation avgDays>teamAvgDays*2;
      low_rev_per_pa pa>0 AND rev/pa<avgRevPerPA*0.5; declining prevSO>3 AND
      so<prevSO*0.5; dormant days since last_so > 10.

# 7. AUTH, ROLES, SECURITY, SETTINGS  (platform layer)

ROLES & PERMISSIONS (tbl_ftth_user.hak_akses):
  Administrator : all permissions (*)
  Operator      : view_all_analytics, export, edit_data
  Analyst       : view_all_analytics, export
  Viewer        : view_basic
  Admin-only modules: user_management, email_recipients, access_stats, settings.

AUTH FLOW:
  login -> bcrypt verify -> on success regenerate session, set keys
    {id_user, nama_user, username, hak_akses, logged_in, login_time,
     last_activity, must_change_password}.
  Lockout: failed_attempts increments; at lockout_threshold (default 5) set
    locked_until = now + lockout_duration_minutes (default 15).
  Every request gated centrally: not-logged-in redirect; idle timeout
    (session_timeout_minutes, default 60); force-logout (force_logout_at >
    login_time) & is_active=0; must-change-password redirect; maintenance mode
    (non-admin blocked); CSRF token on non-GET AJAX.

ACCESS LOG (tbl_ftth_access_log): append-only; action_type in {login_success,
  login_failed, logout, module_view, export, create, update, delete,
  password_change}; fields user_id, username, action_type, module, target,
  ip_address, user_agent, session_id(hashed), detail(JSON), created_at.
  IP order: CF-Connecting-IP -> X-Forwarded-For -> X-Real-IP -> REMOTE_ADDR.
  Retention: prune older than log_retention_days (Sun 04:00).
  [BQ] partition by DATE(created_at).

SETTINGS (tbl_ftth_setting key/value): app branding/logo, password rules,
  lockout_threshold/duration, session_timeout_minutes, working_hours_start/end
  (off-hours detection), email_blast_enabled (email kill-switch),
  maintenance_mode/message, log_retention_days, welcome_* popup.
